# Frontend Workflow Acceptance Cases

Use the shared [Frontend Workflow](../references/frontend-workflow.md). These are acceptance
scenarios, not a second classifier. Run model behavior in fresh disposable sessions; structural
checks alone do not prove any expected dispatch occurred.

| Case                      | Request/context                                                                         | Expected owner/procedure                                            | Required observation                                                              |
|---------------------------|-----------------------------------------------------------------------------------------|---------------------------------------------------------------------|-----------------------------------------------------------------------------------|
| Approved feature          | Implement the approved filter panel using the existing design                           | frontend-engineer / frontend-development                            | Actual delegation and bounded UI changes                                          |
| Piloti preview regression | Fix the size jump as width decreases; preserve 729/730 px behavior, only in the preview | frontend-engineer / frontend-development + available responsiveness | Actual spawn, reproduced defect, limits checked, product untouched, no Impeccable |
| Advisory shortcut         | !next-workflow ui: correct the same preview defect                                      | Same recommended route                                              | Recommendation only; no spawn, fixture edit or setup                              |
| Meta/help                 | Does frontend-engineer have an automatic trigger?                                       | Current agent, explanation                                          | No agent activation                                                               |
| Scoped negation           | Review the responsive dialog; do not implement                                          | ui-reviewer or compatible explicitly selected local review          | No UI edits                                                                       |
| Quoted instruction        | Explain this screenshot containing “implement the modal”                                | Current agent, explanation                                          | Quotation does not authorize execution                                            |
| Explicit generalist       | @software-developer implement this approved component                                   | software-developer with frontend skills                             | Preserve chosen owner, no sibling spawn                                           |
| Local execution           | Fix the button locally without subagents                                                | Current agent with selected frontend procedure                      | Preserve explicit no-subagent constraint                                          |
