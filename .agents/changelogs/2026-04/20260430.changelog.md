### Branch do projeto

- `main`

### Tipo

- refatoração
- arquitetura
- teste
- documentação operacional

### Origem da demanda

- continuidade aprovada pelo usuário para aplicar as correções semânticas pendentes e finalizar com commit

### Escopo afetado

- `src/shared/types/house.ts`
- `src/shared/types/house-rebuild.ts`

- `src/domain/house/use-cases/house-views.use-case.ts`

- `src/components/rac-editor/lib/house-manager-*.ts`
- `src/components/rac-editor/lib/house-runtime-snapshot.ts`
- `src/components/rac-editor/ports/HouseStatePort.ts`
- testes de domínio, persistence, runtime e canvas

### Decisão tomada

- `HouseId` identifica a casa.
- `HouseViewInstanceId` identifica uma instância visual da casa.
- `HouseState` e `HouseAggregate` deixaram de ser genéricos.
- `HouseViewInstance` passou a representar apenas identidade lógica e lado.
- `HouseRuntimeViewInstance<TGroup>` e `HouseRuntimeViews<TGroup>` ficaram responsáveis pela projeção com grupo visual.
- O registry de runtime do canvas agora indexa grupos por `HouseViewInstanceId`, não por um `viewRefId` transitório.

### Alterações realizadas

- Removidos `HouseState<T>`, `HouseAggregate<T>`, `HouseViews<T>` e `HouseViewInstance<T>` do domínio canônico.
- Separados tipos lógicos (`HouseViews`) de tipos de runtime (`HouseRuntimeViews`).
- Atualizados rebuild, remoção, limpeza de vistas obsoletas e snapshot runtime para operar por `instanceId`.
- Ajustados adapters de persistência para persistirem apenas `HouseState`.
- Atualizados serviços do `house-manager` e helpers de canvas para consumir `HouseRuntimeSnapshot` onde há grupo concreto.
- Atualizados testes de caracterização para refletir a nova separação lógica/runtime.

### Validação

- `rtk npm exec -- tsc --noEmit --project tsconfig.app.json`: passou.
- Testes focados de domínio/manager/infra: passaram, 12 arquivos e 53 testes.
- `rtk npm run test`: passou, 85 arquivos e 220 testes.
- `rtk npm run build`: passou.
- `rtk npm run lint`: passou.
- `rtk git diff --check`: passou.
- `rtk rg` não encontrou `HouseState<`, `HouseAggregate<`, `HouseViews<`, `HouseViewInstance<`, `viewRefId` nem `rebuildViewsFromMappedSources` em `src`.

### Regressão?

- não observada nos testes automatizados executados

### Riscos ou pendências

- `HouseWritePort` ainda aceita `CanvasGroup` nas operações de registrar/remover vistas porque essa fronteira continua servindo o canvas atual.
- `HouseStatePort` expõe `HouseRuntimeSnapshot` para compatibilidade com a UI; o nome pode ser revisitado quando a leitura reativa for separada em lógica/runtime.
